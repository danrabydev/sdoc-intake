## Settled (decided)

1. **v1 grammar is static.** Tag kinds: `section`, `requirement`, `control`, `release`. Edges: `refines`, `conforms_to`, `delivers`, `uses`. No grammar editor in v1. A notation file is the StrictDoc import/export contract.
   - **TODO:** Write that notation file (contents not defined here). Suggested path: `docs/design/strictdoc-notation.md`.
2. **Catalogs are global documents** (`isCatalog`; standards also `isStandard`). Standards (NIST, STIG) are referenced, never copied. Non-standard catalogs may be copied as templates.
3. **Document = tree of tags** with title; parent must be a section (or null at top). Kind-specific metadata tables may be empty (outline/mind-map mode).
4. **Traces are a separate edge table**, not document structure.
5. **No separate security document.** Security is referenced from the requirement via `conforms_to` + verification note when complete.
6. **Product requirements** are suite-level constraints; apps, shared services, and infrastructure are separate documents. App requirements **uses** shared services (not `refines`).
7. **RBAC is project-scoped** (identity, role, project) except catalog steward, which is global.
8. **Postgres is source of truth**; DevOps is client. Extension documents unused fields.

## Draft role matrix (proposed)

SDLC-named roles:

| Role | Scope | Capabilities (summary) |
|------|--------|-------------------------|
| **Reader** | Project | Read project, tags, edges, catalogs; no edits, no sync |
| **Author** | Project | BA/requirements engineer; create/edit sections, requirements, traces; cannot publish catalogs, ship releases, or change grants |
| **Developer** | Project | Read project; create/update work items already mapped from requirements; cannot change requirement text or catalogs |
| **Tester** | Project | Read project; write verification notes on requirements/controls; cannot change statement, tree, or catalogs |
| **Release manager** | Project | Set `delivers` edges; move release to shipped; shipped release stays frozen including `delivers` edges |
| **Security** | Project | Author requirements/controls and attach `conforms_to` to standards; cannot publish/edit standard catalogs |
| **Catalog steward** | **Global** (not a project grant) | Publish/version NIST, STIG, other catalogs; standards referenced never copied; project roles cannot edit them |
| **Project admin** | Project | Grants on that project, DevOps connection, role assignment; not catalog steward |
| **Auditor** | Project | Read-only across project including verification notes and sync history; no writes |

One person may hold more than one role. Catalog steward is the only role outside a project.
